# 교통 관제탑 (Traffic Control Tower)

CCTV 영상에 YOLO 를 적용한 결과와 BEV(위에서 본 화면) 속도 측정, 신호 타임라인을
하나의 웹 화면에서 볼 수 있는 관제 사이트입니다.
하늘색·아이보리·흰색·회색을 기본으로 하고 주황을 포인트로 쓴 절제된 관제 콘솔 화면이며,
모든 연령대가 읽기 쉽도록 본문 17px(확대 시 20px), 넉넉한 조작 영역, 높은 명도 대비를 지켰습니다.

## 1. 실행 방법

```bash
cd ~/Documents/한이음/관제탑

# 1) 필요한 것 설치 (한 번만)
pip install flask

# 2) 실행
python 한번에확인.py
```

`한번에확인.py` 는 포트 확인 → 서버 실행 → 영상 전송 점검 → 브라우저 열기까지
한 번에 해 줍니다. 서버만 켜려면 `python app.py` 를 쓰면 되고,
주소는 **http://127.0.0.1:5050** 입니다.

> **맥에서 포트 5000 을 쓰지 마세요.** macOS 몬터레이부터 AirPlay 수신 모드가
> 5000 번을 점유합니다. 이 상태로 `http://127.0.0.1:5000` 에 접속하면
> Flask 가 아니라 AirPlay 가 응답해 **액세스 거부(403)** 가 뜹니다.
> 그래서 기본 포트를 5050 으로 바꿨습니다.

> `cache/` 의 분석 데이터와 `web_media/` 의 웹 재생용 영상이 이미 들어 있어
> 바로 실행하면 됩니다.

### 영상이나 CSV 를 새로 만들었다면

```bash
python precompute.py --force   # 속도 데이터 다시 계산 (약 15초)
python transcode.py            # 웹 재생용 H.264 변환
```

## 1-1. 영상 코덱에 대해 (중요)

`final.py` 가 만드는 결과 영상은 코덱이 **MPEG-4 Part 2** (`cv2.VideoWriter_fourcc(*'mp4v')`) 입니다.
이 코덱은 **크롬·엣지·파이어폭스의 `<video>` 태그가 재생하지 못합니다.**
HTML5 비디오가 지원하는 코덱은 H.264 / VP9 / AV1 뿐입니다.

그래서 `transcode.py` 로 모든 영상을 H.264 로 다시 인코딩해 `web_media/` 에 넣어 두었습니다.
서버는 `web_media/` 에 변환본이 있으면 그것을, 없으면 원본을 보냅니다.
변환하면서 `moov` 를 파일 앞으로 옮겨(faststart) 브라우저가 곧바로 재생을 시작합니다.

| | 용량 |
|---|---|
| 원본 (mp4v) | 약 10.0 GB |
| 변환본 (H.264) | 약 1.9 GB |

앞으로 이 문제를 아예 없애려면 `final.py` 의 fourcc 를 바꾸면 됩니다.

```python
fourcc = cv2.VideoWriter_fourcc(*'avc1')   # mp4v 대신
```

## 1-2. 영상이 안 나올 때

```bash
python 진단.py
```

파일 코덱, 실행 중인 서버 버전, 실제로 전송되는 영상까지 확인해 원인과 할 일을 알려 줍니다.

가장 흔한 원인은 **서버를 다시 켜지 않은 것**입니다.
Flask 는 코드를 고쳐도 자동으로 다시 읽지 않으므로,
`app.py` 가 이미 떠 있었다면 터미널에서 `Ctrl + C` 로 끄고 다시 실행해야 합니다.

그다음은 **브라우저 캐시**입니다. 강제 새로고침으로 지워집니다.
맥은 `Command + Shift + R`, 윈도우는 `Ctrl + Shift + R`.

## 1-3. 웹앱(PWA) 으로 설치하기

`한번에확인.py` 를 실행하면 화면에 **휴대폰용 https 주소**가 나옵니다.
그 주소로 접속한 뒤

- **아이폰(사파리)** : 공유 버튼 → `홈 화면에 추가`
- **안드로이드(크롬)** : 메뉴 → `앱 설치` 또는 `홈 화면에 추가`

하면 일반 앱처럼 아이콘이 생기고, 주소창 없이 전체 화면으로 열립니다.
화면 파일은 서비스 워커가 캐시하므로 두 번째부터는 즉시 뜹니다.
(영상과 데이터는 캐시하지 않고 항상 서버에서 새로 받습니다.)

## 1-4. 현장 모드 — 가까이 가면 자동으로 열립니다

오른쪽 위 **현장 모드** 버튼을 켜면 GPS 로 위치를 계속 확인하다가,
등록된 교차로 반경(기본 150m) 안으로 들어오면 그 지점의 CCTV 화면이 자동으로 열립니다.

| 장소 | 묶인 영상 | 좌표 |
|---|---|---|
| 올림픽공원 교차로 | 올림픽공원 ①②③ | 37.517686, 127.112864 (실측) |
| 올림픽공원 남단 교차로 | 올림픽공원 남단 | 37.514500, 127.123000 (대략값) |
| 워커힐 교차로 | 워커힐 ①②③ | 37.547700, 127.098300 (대략값) |

같은 교차로를 찍은 ①②③ 은 **하나의 장소**로 묶여 있습니다.
도착하면 첫 번째 영상이 열리고, 화면 위 초록 띠의 `1` `2` `3` 버튼으로 다른 회차를 볼 수 있습니다.

### 좌표 보정 (중요)

올림픽공원 좌표는 `bev_v2_위경도.py` 에 있는 기준점 4개의 평균이라 정확합니다.
**남단과 워커힐은 대략값**이라 현장에서 한 번 보정해 주셔야 합니다.

1. 휴대폰으로 접속해 **현장 모드** 켜기
2. 상태 띠의 **위치 설정** 누르기
3. 해당 교차로에 서서 **이 자리로 지정** 누르기

누른 순간의 GPS 좌표가 `places.json` 에 저장됩니다. 코드를 고칠 필요는 없습니다.
반경도 같은 화면에서 20~2000m 사이로 바꿀 수 있습니다.

### 휴대폰이 접속되지 않을 때

`한번에확인.py` 를 실행하면 노트북에서 **접속 안내 페이지**(`/connect`)가 자동으로 열립니다.
와이파이·핫스팟 등 이 컴퓨터가 가진 모든 주소를 QR 로 보여 주니 카메라로 찍으면 됩니다.

그래도 "사이트에 연결할 수 없음" 이 뜨면 아래를 순서대로 확인하세요.

| 확인할 것 | 방법 |
|---|---|
| 서버가 외부에 열려 있는지 | 실행 화면 `[6] 네트워크 주소로 접속 확인` 에 `가능` 이 하나라도 있어야 합니다 |
| 맥 방화벽 | 처음 실행할 때 뜨는 "들어오는 네트워크 연결을 허용" 창에서 **허용**. 이미 거부했다면 시스템 설정 → 네트워크 → 방화벽 → 옵션에서 python 을 허용으로 바꾸세요 |
| 게스트 와이파이 | 게스트망은 단말끼리 통신이 막혀 있습니다. 일반 와이파이로 바꾸세요 |
| 아이폰 비공개 릴레이 | 설정 → Apple 계정 → iCloud → 비공개 릴레이 끄기 |
| VPN | 휴대폰·노트북 양쪽 모두 끄기 |
| 공유기 설정 | '단말 간 통신 차단 / AP isolation' 을 끄세요 |

**가장 확실한 우회 방법**은 노트북에서 개인용 핫스팟을 켜고 휴대폰을 거기에 연결하는 것입니다.
이 경우 `한번에확인.py` 가 핫스팟 주소도 같이 보여 줍니다.

### GPS 를 쓰려면 HTTPS 가 필요합니다

브라우저는 보안상 `https://` 또는 `localhost` 에서만 위치 정보를 내줍니다.
`한번에확인.py` 가 자체 서명 인증서를 만들어 `https://내PC주소:5050` 으로 띄워 줍니다.
휴대폰에서 처음 접속할 때 **"이 연결은 비공개가 아닙니다"** 경고가 뜨는데,
직접 만든 인증서라서 그런 것이니 `고급 → 이동`을 누르면 됩니다.
노트북과 휴대폰이 **같은 와이파이**에 있어야 합니다.

위치 오차는 도심에서 보통 10~50m 입니다. 반경을 너무 좁게(50m 미만) 잡으면
현장에 서 있어도 전환이 안 될 수 있습니다.

## 1-5. 인터넷에 배포하기 (GitHub Pages)

와이파이 문제 없이 어디서나 접속하려면 정적 사이트로 배포하면 됩니다.
GitHub Pages 는 HTTPS 를 기본 제공하므로 **GPS 현장 모드도 그대로 동작합니다.**

```bash
python build_static.py             # docs/ 폴더 생성 (영상 재인코딩 포함, 약 15분)
```

`docs/` 안에 서버 없이 돌아가는 완성본이 만들어집니다.

| 항목 | 내용 |
|---|---|
| 전체 용량 | 약 474 MB |
| 가장 큰 파일 | 78 MB (깃허브 제한 100MB 통과) |
| 영상 | 854x480 로 재인코딩 (1.8GB → 458MB) |
| 데이터 | API 응답을 JSON 으로 미리 구움 (3.3MB) |

화질을 바꾸려면 `--quality 360p` 또는 `--quality 720p` 를 붙이세요.
화면만 다시 굽고 영상은 그대로 두려면 `--skip-video` 를 붙입니다.

### 올리는 순서

```bash
cd ~/Documents/한이음/관제탑
git init
git add .
git commit -m "교통 관제탑"
git branch -M main
git remote add origin https://github.com/<아이디>/<저장소>.git
git push -u origin main
```

그다음 저장소 **Settings → Pages** 에서

- Source : `Deploy from a branch`
- Branch : `main` / 폴더 : `/docs`

를 고르고 저장하면 몇 분 뒤 `https://<아이디>.github.io/<저장소>/` 주소가 나옵니다.

`.gitignore` 가 원본 영상(`web_media/`), 분석 캐시, 인증서를 제외하므로
실제로 올라가는 것은 `docs/` 와 소스 코드뿐입니다.

### 서버판과 다른 점

| | Flask 서버판 | GitHub Pages 정적판 |
|---|---|---|
| 실행 | `python 한번에확인.py` | 접속만 하면 됨 |
| 접속 범위 | 같은 와이파이 | 인터넷 어디서나 |
| HTTPS | 자체 인증서(경고 발생) | 정식 인증서 |
| 영상 화질 | 원본 720p | 480p |
| 현장 좌표 저장 | `places.json` (모든 기기 공유) | 브라우저에만 저장 (기기별) |
| 영상 재생 테스트 페이지 | 있음 | 없음 |

좌표를 모든 사람에게 공통으로 적용하려면, 현장에서 보정한 뒤
`places.json` 값을 `config.py` 의 `PLACES` 에 옮겨 적고 다시 빌드하면 됩니다.

```bash
python precompute_predict.py
```

## 2. 화면 구성

**1단계 — 장소 고르기**
7개 영상(올림픽공원 ①②③, 올림픽공원 남단, 워커힐 ①②③)이 카드로 나옵니다.
카드에는 인식한 차량 수, 평균 속도, 위험 차량 수가 미리 보입니다.

**2단계 — 관제 화면**

| 영역 | 내용 |
|---|---|
| 화면 전환 | `차량 인식`(YOLO) ↔ `평면 변환`(BEV) ↔ `디지털 트윈`(도로 도면 위 재현) — 재생 위치를 유지한 채 전환 |
| 위반 감지 | 정지선 위반·꼬리물기 목록. 누르면 그 장면으로 이동하고, 재생 중 해당 시점이 오면 알림이 뜹니다 |
| 경로 예측 | LSTM 이 예측한 30프레임(약 1초) 뒤 경로를 주황 점선으로 표시 (평면 변환·트윈 화면에서만) |
| 지금 신호 | 재생 시간에 맞춰 신호 CSV 를 읽어 방향별 초록/노랑/빨간불 표시 |
| 지금 지나가는 차 | 그 순간 보이는 차량 수, 평균 속도, 가장 빠른 차, 차량별 속도 목록 |
| 위험도 | 그 순간의 안전/주의/위험 비율과 큰 글씨 판정 |
| 위험도 띠 | 영상 전체를 색 띠로 요약 — 클릭하면 그 시각으로 이동 |
| 영상 전체 요약 | 차량별 표(정렬·필터·`이 장면 보기` 버튼) |

키보드: `스페이스` 재생/멈춤, `←` `→` 10초 이동.
오른쪽 위 `글씨 크게` 버튼으로 전체 글자 크기를 17px → 20px 로 키울 수 있습니다.
아이콘은 모두 선형 SVG 이며 이모지·그라데이션·장식 효과는 쓰지 않았습니다.

## 3. 위험도 판정 기준

제한속도 50km/h 기준입니다. (`config.py` 의 `speed_limit` 에서 장소별로 바꿀 수 있습니다.)

| 판정 | 기준 |
|---|---|
| 안전 | 50km/h 미만 |
| 주의 | 50 ~ 65km/h |
| 위험 | 65km/h 이상 |
| 측정 부족 | 화면에 0.5초(15프레임) 미만으로만 잡힌 차량 |

측정값에는 추적 ID 가 바뀌면서 생기는 튀는 값이 섞여 있습니다. 그래서

- **150km/h 초과 값은 측정 오류로 보고 버립니다** (`MAX_PLAUSIBLE_SPEED`)
- **차량 판정은 순간 최고속도가 아니라 "꾸준히 낸 속도"** 로 합니다
  (초 단위 최고속도의 90퍼센타일, `STABLE_PERCENTILE`)
- 아주 짧게만 잡힌 차량은 판정에서 빼고 `측정 부족` 으로 표시합니다

`순간 최고` 열은 참고용으로 그대로 보여 줍니다.

### ⚠️ 데이터에 대한 참고

같은 기준으로 계산했을 때 장소별 결과가 이렇게 갈립니다.

| 장소 | 판정 차량 | 평균 속도 | 위험 비율 |
|---|---|---|---|
| 워커힐 ①②③ | 287~344대 | 41~44 km/h | 6~8% |
| 올림픽공원 ①②③ | 686~947대 | 51~62 km/h | 31~42% |
| 올림픽공원 남단 | 3,210대 | 60 km/h | 40% |

워커힐 쪽은 도심 교차로 속도로 자연스럽지만, 올림픽공원 쪽은 눈에 띄게 높습니다.
`bev_v1_횡단보도.py` 에서 올림픽공원은 20m × 6.5m 기준 사각형을 두고
위쪽으로 80m 까지 확장(`EXPAND_TOP = 80.0`)했기 때문에, 기준 사각형에서 먼 곳의
좌표 오차가 커져 속도가 과대평가되었을 가능성이 큽니다.
발표·제출용으로 쓰기 전에 기준점 4개와 실제 거리를 다시 한 번 확인해 보시길 권합니다.

## 5. API

| 주소 | 설명 |
|---|---|
| `GET /api/videos` | 영상 목록과 요약 |
| `GET /api/video/<id>` | 선택한 영상의 타임라인·차량표·신호 전체 |
| `GET /api/signal/<id>` | 신호 타임라인만 |
| `GET /media/<id>/yolo` | YOLO 결과 영상 (구간 요청 지원) |
| `GET /media/<id>/bev` | BEV 속도 영상 (구간 요청 지원) |
| `GET /api/health` | 서버·데이터 상태 확인 |
| `GET /api/places` | 등록된 교차로 좌표와 묶인 영상 |
| `POST /api/places/<id>` | 좌표 저장 (`{"lat":..,"lon":..,"radius_m":..}`) |
| `GET /api/nearest?lat=&lon=` | 가장 가까운 교차로와 거리 |
| `GET /media/<id>/twin` | 디지털 트윈 영상 |
| `GET /api/predict/<id>` | 이동경로 예측 경로 |
| `GET /manifest.webmanifest` | 웹앱 정보 |
| `GET /sw.js` | 서비스 워커 |
| `GET /test` | 영상 재생 최소 테스트 |

## 6. 영상을 새로 추가하려면

1. `핵심 소스코드/final.py` 로 `_yolo.mp4`, `_bev_velocity.mp4`, `_speed.csv` 를 만들고
2. `signal_time/` 에 신호 CSV 를 넣은 뒤
3. `config.py` 의 `DATASETS` 에 항목을 하나 추가하고
4. `python precompute.py <새 id>` 와 `python transcode.py <새 id>` 를 실행하면
   목록에 나타납니다.
